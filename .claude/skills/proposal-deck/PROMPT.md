# 依頼プロンプト（Claude Code / Codex 共通）

スキルが入っていれば、**添付＋案件メモ＋最後の一文**だけで同じ形式のデッキが出る。
Codex ではスキルを明示的に呼ぶと確実（`$proposal-deck`）。

## 1. 通常の依頼（スキル導入済み）

```
$proposal-deck          ← Codex のときだけ先頭に付ける（Claude Code では不要）

添付：<前回の提案書.pptx>

【<件名>（新設ライン／アドオン 等）】<案件No>

＜案件背景＞
・…
・<稼働時期>稼働（<試運転開始>から試運転）→<発注期限>には発注が必要
・…

＜内容について＞
ST1｜<検査名>（上流）
・Phoenix Vision＋Edge
・カメラ <台数>（<画素数・色>×n）
・照明 <種類>×n
・装置 搬送あり／治具あり／排出あり（<方式>）／制御あり
＜備考＞
・<搬送方法・検査方法>
・<NG排出の流れ>
・<タクト>（生産量：<n>本/時）
・不良：<項目>

ST2｜…（同上）

▼検証に際して
<重視点、検証日>

提案書のスライドを他依頼みたいに作成してほしい。添付資料を参考にしてください。
```

書かなくてよいもの：デザインの指定、章立て、スライド枚数。すべて正解例で固定されている。

書いておくと良いもの：客先の正式社名（無ければ表紙は `〇〇株式会社　御中` になる）、
提案書の日付（無ければ実行日）。

## 2. スキルが使えない環境での依頼（フォールバック）

Codex の古いバージョンなどでスキルが読み込まれない場合は、スキルフォルダの場所を直接伝える:

```
<スキルの場所>/SKILL.md を読んで、その手順どおりに提案書を作ってください。
正解例 <スキルの場所>/examples/two-station-line/build_deck.py をコピーして CONTENT だけを
下の案件メモで書き換え、型関数・座標・色・文言の作法は変えないでください。
最後に render した全ページ画像を確認し、問題があれば直してから渡してください。

添付：<前回の提案書.pptx>
（案件メモ）
```

## 3. 出力がずれたとき

正解例と違う見た目になったら、まず次を確認させる:

```
build_deck.py の CONTENT 以外を変更していないか差分を見せてください。
s_ で始まる型関数・TEMPLATE・座標を正解例から変えていたら元に戻してください。
```

# 章立てと内容の作り方

**実装の正解は `examples/two-station-line/build_deck.py`。** このファイルはその設計意図の説明。
食い違ったら正解例のほうに合わせる。

## 標準構成

```
1    表紙              （テンプレのスライドを文字差し替え）
2    目次              （同上。章名だけ入れ替える）
3    中扉 Ⅰ
4    Ⅰ. 現状のご状況と課題        2カード型 ＜ご状況＞＜課題＞ + 結論バナー
5    中扉 Ⅱ
6-10 Ⅱ. ご提案                   フロー型（全体構成）→ 各ST/各系統の詳細 →
                                 ご提供範囲（納入スコープ）→ タクト/性能適合
11   中扉 Ⅲ
12-13 Ⅲ. 導入スケジュール        ガント型 + 今後の進め方（検証ステップ型）
14   中扉 Ⅳ
15-16 Ⅳ. ご検討にあたっての比較観点  比較表 + 導入効果
17   中扉 Ⅴ Appendix
18-  Ⅴ. Appendix                 テンプレのまま丸ごと流用（会社概要・事業概要・
                                 プロダクト・導入企業・上場・強み・必要性・効果）
```

章の数が変われば中扉の `Ⅰ.〜Ⅴ.` と目次を揃えて付け替える。テンプレの中扉が足りなければ
`scripts/pptx_tool.py add_slide` で複製する（正解例 `build_deck.py` は本編スライドの不足分を自動で複製する）。

## 各スライドの考え方

**リード文（idx13）が主役。** 「■〜いたします。」の一文でそのスライドの結論を言い切る。
図表はその証拠。リード文を読むだけで提案が通るように並べる。

**現状と課題**: 左に事実（ご状況）、右に困りごと（課題）。最後の1項目は赤太字にして
「だから検査機が要る」に接続する。下のバナーで次章への橋を架ける。

**ご提案（全体構成）**: まずライン全体のフロー図で「どこに何を置くか」を示す。
対象外の工程（充填機・ラベラーなど）は `MIDGRAY`、こちらが納める箱は `NAVY` にして、
担当範囲が一目で分かるようにする。その下に `point_row` 3行で「なぜこの構成か」。

**各ステーションの詳細**: 左に＜検査概要＞（文章）、右に構成表（区分/仕様/数量）。
**見積書の品目と列構成を揃える**と、商談で見積書と並べて説明できる。
下のバナーにタクトと検出対象を置く。

**ご提供範囲**: 区分 / 主な内容 / 当社ご提供 / 備考 の4列。`●`＝当社、`△`＝協議、`―`＝客先手配。
搬送・排出まで含むフルセット案件では、これがあると「どこまでやるのか」の往復が消える。

**タクト適合**: 上に全体の帯（処理時間＋バッファ）、下に工程別の内訳表。
**実測値がないなら全行に「当社想定」と書く**。断定しない。

**スケジュール**: 稼働日から逆算する。発注が必要な月を `RED` のバーにして、
下のバナーで「◯月中のご発注をお願いします」と言い切る。ここが提案書の実質的な締め。

**比較観点**: 観点 / ご確認いただきたいポイント / 当社 / A社タイプ / B社タイプ。
自社列だけ `LTBLUE` で塗る。他社を貶さず、観点の提示に徹するほうが効く。

**導入効果**: 定量（Before→After）＋定量以外3枚（基準の一定化・採用教育負担・データ活用）。
新設ラインなど「現状の工数」が存在しない案件では、Before を「目視では対応不可」にする。

## やらないこと

- 金額はスライドに載せない（見積書の領域）。載せる方針なら明示的に確認する
- 前案件の検証結果スライドを流用しない。写真も数値も案件固有
- 1スライドに2つのメッセージを詰めない。分ける

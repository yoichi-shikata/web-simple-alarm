# 正解例：2ステーション構成の新設ライン向け提案書

「理想形」として採用された提案書と**同じ構成・同じ書き方・同じ座標**で組むビルドスクリプト。
公開リポジトリのため、内容は架空のサンプル案件（PETボトル、3,600本/時）に置き換えている。

- `build_deck.py` … 本体。`CONTENT` を書き換えるだけで新しい案件のデッキになる
- `request.md` … この正解例に対応する依頼文の例（ユーザーからの入力の典型形）

## 出来上がるデッキ（30枚）

| # | スライド | 型 | `CONTENT` のキー |
|---|---|---|---|
| 1 | 表紙 | テンプレの文字差し替え | `customer` `title` `date` |
| 2 | 目次 | 章名の差し替え | `sections` |
| 3 | 中扉 Ⅰ | 〃 | `sections[0]` |
| 4 | 現状のご状況と課題 | 2カード（状況／課題）＋結論バナー | `genjou` |
| 5 | 中扉 Ⅱ | | `sections[1]` |
| 6 | ご提案｜全体構成 | 工程フロー5箱＋ポイント3行 | `overview` |
| 7〜 | ST1, ST2 … の詳細 | 左：検査概要カード／右：構成表（区分/仕様/数量）＋バナー | `stations[]` |
| | ご提供範囲（納入スコープ） | 表（●当社／△協議／―貴社） | `scope` |
| | 処理時間｜タクト適合 | 処理時間の帯＋内訳表（当社想定） | `tact` |
| | 中扉 Ⅲ | | `sections[2]` |
| | 導入スケジュール | ガント＋発注依頼バナー | `schedule` |
| | 今後の進め方 | 3ステップ＋2カード（重点確認点／検証項目） | `next` |
| | 中扉 Ⅳ | | `sections[3]` |
| | ご検討にあたっての比較観点 | 5観点×3社の比較表（自社列のみ淡青） | `compare` |
| | 導入効果 | Before→After＋定量以外の効果3枚 | `effect` |
| 17〜30 | 中扉 Ⅴ＋Appendix | テンプレのまま | （触らない） |

ステーションの数に応じて本編スライドは自動で増減する（1STなら29枚、3STなら31枚）。

## 案件メモ → CONTENT の対応

| 案件メモの項目 | 入れる先 |
|---|---|
| 案件背景（増産・新設・PJT予算） | `genjou.status` |
| 稼働時期・試運転開始 | `genjou.status`、`schedule` |
| タクト・生産量 | `genjou.status`、`tact`、各STの `banner` |
| なぜ検査機が必要か（目視不可など） | `genjou.issues`（最後の1項目を赤太字に） |
| ST名・カメラ・照明・装置（搬送/治具/排出/制御） | `stations[].spec` |
| ST備考（搬送方法・検査内容・排出方法） | `stations[].summary` |
| 不良項目 | 各STの `banner`、`next.items` |
| ライン構成（前後の設備） | `overview.flow`（他社設備は `"ext"`、当社は `"ours"`） |
| 発注期限 | `schedule.rows` の `"order"` 行と `schedule.banner` |
| 検証日・重視点 | `next` |

**スライドに出さないもの**: 予算感、競合の有無、支払条件、社内の担当経緯、客先担当者の個人名。
これらはメモに書かれていても営業の内部情報なので、デッキには入れない。
